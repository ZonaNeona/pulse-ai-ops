# 0002. Один реестр инструментов, несколько исполнителей; LangGraph — для документов

**Статус:** принято

## Контекст

Есть два разных класса задач:

- свободный вопрос («что с зависшими у Кузнецовой и что предложить?») — нужен агент, который сам выбирает инструменты;
- разбор входящего документа — строгая последовательность шагов, остановка на решении человека и продолжение через минуты или дни.

Кроме того, публичный стенд должен работать, когда модель или Hermes недоступны.

## Решение

**Копилот.** Инструменты описаны один раз в `agents/tools.py` (11 штук: 10 на чтение и `draft_task`, который создаёт только черновик). Их используют:

1. `agents/quick.py` — частые вопросы с ясным намерением отвечаются вызовом инструментов без модели;
2. Hermes Agent — через MCP-сервер `agents/mcp_server.py`, список инструментов генерируется из реестра;
3. встроенный цикл `agents/runner.py` — OpenAI-совместимый tool calling через `core/llm.py`, если Hermes не настроен или не ответил.

Маршрутизатор выбирает самый дешёвый путь, который может ответить честно: готовый ответ → регламенты → Hermes → встроенный цикл → «модель недоступна». Подтвердить черновик может только человек через API или кнопку в Telegram — у агента такого инструмента нет.

**Документы.** `modules/docs/graph.py` — LangGraph `StateGraph`: `extract → validate → review → post | reject` (подробно — в 0005).

## Последствия

- Нечему расходиться: веб, Hermes и бот видят одни и те же инструменты.
- Без модели стенд остаётся полезным, а ответ прямо говорит, что модель не использовалась.
- Hermes запускает MCP-сервер отдельным процессом, поэтому сессия посетителя передаётся через файл хода, а ходы Hermes идут по одному.
