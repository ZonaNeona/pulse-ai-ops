# ADR-001: Архитектура портов и адаптеров (Hexagonal Architecture)

## Статус
Принято (Accepted)

## Контекст
Платформа «Пульс» разрабатывается как открытый демонстрационный стенд и промышленная основа для интеграции AI-агентов в бизнес-процессы B2B-компаний. Реальные корпоративные заказчики используют разнородные системы: Битрикс24 (облачный или коробочный REST API) и 1С:ERP / 1С:УНФ (OData / HTTP-сервисы).
Для открытого демо-стенда и локальной разработки критически важно:
1. Запускаться из коробки без привязки к чужому платному инстансу CRM/ERP.
2. Гарантировать воспроизводимость данных и независимость тестов.
3. Позволять в один клик переключиться на реальный портал Битрикс24 или живую базу 1С без переписывания бизнес-логики модулей.

## Решение
Использован архитектурный паттерн **Порты и Адаптеры (гексагональная архитектура)**:

1. **Порты (Абстрактные интерфейсы):**
   - `pulse.crm.port.CrmPort` — методы чтения сущностей CRM: лиды, сделки, активности (звонки), стадии, пользователи.
   - `pulse.erp.port.ErpPort` — методы чтения сущностей ERP: заказы клиентов, реализации, счета на оплату, поступления ДС, остатки.

2. **Адаптеры:**
   - **Эмуляторы (`CRM_MODE=emulator`, `ERP_MODE=emulator`):** Реализуют порты поверх снапшотов реальных сущностей «Норд Инжиниринг» в SQLite (`pulse.crm.emulator.EmulatorCrmAdapter`, `pulse.erp.emulator.EmulatorErpAdapter`).
   - **Живые адаптеры (`CRM_MODE=live`, `ERP_MODE=live`):**
     - `pulse.crm.rest.BitrixRestAdapter` — асинхронный клиент Битрикс24 REST API с обработкой rate limits (`rest.client`) и постраничной пагинацией.
     - `pulse.erp.odata.ODataErpAdapter` — клиент к стандартному OData-интерфейсу 1С:Предприятие 8.3 с Basic/OAuth авторизацией.

3. **Синхронизация:**
   Сервис `pulse.sync.sync_all()` запрашивает данные через интерфейсы портов и сохраняет нормализованный снапшот в SQLite. Модули аналитики («Продажи», «Сверка», «Документы») читают только локальный нормализованный слой.

## Последствия
### Положительные:
- **Zero-Dependency запуск:** любой разработчик или заказчик клонирует репозиторий и запускает `docker compose up` — стенд сразу наполнен живыми данными отдела продаж (8 сделок, 6 звонков с аудио, расхождения 1С).
- **100% изоляция тестов:** 73 теста бэкенда выполняются за секунды на эмуляторе без сетевых запросов.
- **Готовность к продакшену:** для подключения к реальному Битрикс24 достаточно прописать вебхук в `.env`.

### Ограничения:
- Живые адаптеры должны поддерживать обратную совместимость с форматом данных эмулятора при расширении схемы.
