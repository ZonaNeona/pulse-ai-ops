# 0001. CRM и 1С — только через порты

**Статус:** принято

## Контекст

Стенд должен открываться без чужого платного портала и при этом показывать, что подключение настоящего Битрикс24 или 1С — настройка, а не переписывание. Модули продаж, сверки и документов не должны знать, откуда пришли данные.

## Решение

- `crm/port.py` — `CrmPort` (чтение сделок, звонков, задач, лидов, пользователей, воронок) и `B24Transport` (вызов метода REST).
  - `Bitrix24Emulator` отвечает на те же методы REST в формате, снятом с настоящего портала (`crm/fixtures`);
  - `Bitrix24RestAdapter` ходит на живой портал через входящий вебхук и пропускает только методы чтения из белого списка (`ReadOnlyViolation` на всё остальное).
- `erp/port.py` — `ErpPort`; `OneCEmulator` и `OneCODataClient` говорят на стандартном OData 1С.
- `sync.py` забирает данные через порты в локальный SQLite; модули читают только локальный снимок.
- Переключение — `CRM_MODE=live` / `ERP_MODE=live` в окружении.

## Последствия

- Стенд запускается из коробки; тесты идут на эмуляторе без сети.
- Эмулятор обязан повторять формат настоящего API — иначе живой режим сломается незаметно. Поэтому формат взят с реального портала, а не придуман.
- Запись в CRM и 1С с публичного стенда невозможна на уровне адаптера.
