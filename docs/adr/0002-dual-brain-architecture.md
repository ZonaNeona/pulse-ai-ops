# ADR-002: Архитектура «Двух мозгов»: Hermes Agent (MCP) vs LangGraph

## Статус
Принято (Accepted)

## Контекст
В корпоративных AI-системах существуют два принципиально разных класса задач:
1. **Свободный диалог и ad-hoc рассуждения (CoPilot):** пользователь задает неструктурированные вопросы своими словами («Кто из менеджеров не выполнил норму звонков вчера?», «Создай задачу на перезвон клиенту по сделке Норд-22»). Здесь агенту требуется гибкость, вызов произвольного набора инструментов и адаптивный планировщик.
2. **Детерминированные бизнес-процессы (Workflows):** разбор первичных документов (счета, акты, УПД), где критически важна строгая последовательность шагов (`classify` $\to$ `extract` $\to$ `validate` $\to$ `human-approval` $\to$ `post`), персистентность состояния при паузах и гарантия соблюдения правил проверки.

Попытка возложить обе роли на один механизм приводит либо к галлюцинациям в строгих процессах (если использовать чистого ReAct-агента), либо к неповоротливости и невозможности нормального диалога (если загнать весь чат в жесткий стейт-граф).

## Решение
Принята гибридная архитектура с разделением ответственности (**«Два мозга»**):

1. **Мозг 1 — Hermes Agent (Свободный оркестратор поверх FastMCP):**
   - Используется для экрана «Копилот» и Telegram-бота.
   - Подключается к ядру системы через открытый стандарт **Model Context Protocol (MCP)** (`pulse.agents.mcp_server`).
   - Имеет доступ к 11 инструментам чтения (`sales_pulse`, `get_signals`, `team_status`, `docs_queue`, `knowledge_search`) и создания черновиков (`draft_task`).
   - При исчерпании бюджета или недоступности внешнего Hermes включается встроенный локальный Tool-loop runner с кэшем 12 популярных пресетов.

2. **Мозг 2 — LangGraph (Детерминированный конвейер документов):**
   - Используется для модуля «Документы» (`pulse.modules.docs.graph`).
   - Построен как конечный автомат `StateGraph`:
     - Шаг 1: `classify` — определение типа входящего файла (счёт на оплату, договор, УПД).
     - Шаг 2: `extract` — извлечение реквизитов (ИНН, сумма, номер, номенклатура).
     - Шаг 3: `validate` — строгие детерминированные правила сверки с договором в CRM и заказом в 1С.
     - Шаг 4: `review` — прерывание графа (`interrupt_before=["draft"]`) и ожидание действия человека.
     - Шаг 5: `draft` — проведение документа в 1С при подтверждении.
   - Персистентность через `SqliteSaver` с уникальным `thread_id` для каждого документа.

3. **Связка между мозгами:**
   Hermes Agent имеет инструмент `docs_queue` и `review_doc`, позволяющий ему запрашивать статус графа документов и передавать команды на возобновление процесса.

## Последствия
- Полная надежность и предсказуемость в юридически значимом документообороте.
- Гибкий и живой пользовательский интерфейс в чате Копилота.
- Демонстрация владения обоими ключевыми современными фреймворками (MCP/Hermes и LangGraph).
